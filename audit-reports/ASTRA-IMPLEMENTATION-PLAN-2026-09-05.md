## Как действительно выполнить построчный аудит

Сгенерирован `VISUAL-AUDIT-COVERAGE-2026-09-05.json`: **366 файлов,120038 строк** исходников/config/tests/schema на этой рабочей копии. Это инвентаризация, не заявление, что они прочитаны. Все статусы сознательно `not_reviewed`; частичные подтверждённые механизмы описаны выше.

1. Взять одну связанную цепочку, прочитать каждый файл до EOF порциями с непропущенными диапазонами. Записать `reviewedRanges`, функции-источники/потребители и реальные сценарии. Не считать `rg` построчным чтением.
2. Для каждого effect/listener/timer/RAF: кто запускает, кто останавливает, при каких dependency перезапускается, что сохраняется. Для CSS: specificity/cascade, breakpoints, containing block, clipping/stacking context и потребители классов. Для загрузки: источник данных, cache/seed/version, critical/deferred, failed/late response.
3. `code_reviewed` означает полностью прочитанную текущую версию; `verified` — дополнительно прошедшие описанные браузерные/поведенческие проверки. Каждый статус требует evidence. Изменение SHA инвалидирует прошлую отметку.
4. Generated/vendor файлы отмечать отдельно: проверяется генератор, контракт и визуальный результат, не ручная перепись. Картинки/WOFF2 не имеют полезного «построчного анализа» — для них отдельные network/dimensions/quality записи.
5. Обновление реестра: `node audit-reports/refresh-visual-audit-inventory.mjs`. Сохраняет записи для неизменённых SHA, сбрасывает изменённые. Реестр не импортируется сайтом и не увеличивает production bundle.
6. Не прятать пропуски за «проверено всё»: перед завершением вывести непрочитанные файлы, непроверенные маршруты/устройства/состояния и измеренные ограничения.
