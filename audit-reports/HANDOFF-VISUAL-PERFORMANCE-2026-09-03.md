# Памятка после текущего visual/performance-пакета

## Что исправлено в этом пакете

- Home: тёмная полоса над сценой на mobile/tablet, скачок высоты lazy cosmic-stage,
  полноэкранный opacity hand-off, остававшиеся GPU-слои текста и программная рамка h1.
- 404: основная кнопка возврата больше не попадает под CSS плавающей cookie-кнопки
  и не сжимается в круг; генератор больше не предзагружает весь Home вместо NotFound.
- Motion: корректные классы reduced-motion для планет/осколков, восстановление
  canvas после resize, пыль на всю сцену, сохранение её координат при resize,
  очистка desktop-parallax при переходе к compact и сохранение узора plexus.
- Mobile load: шесть невидимых по дизайну картинок не скачиваются (около 101 KiB);
  при расширении viewport они декодируются до общего появления. Canvas сохраняет
  первый кадр, затем движется с мобильным бюджетом 24 fps; offscreen plexus не
  конкурирует с первым экраном. Desktop-вариант и видимые эффекты сохранены.
- Cosmic CSS загружается с Home и админским preview, но не добавляет запрос к
  Google Ads/Meta Apps. Navbar/scroll-trail не создают лишние mobile blur/glow-слои.

## Что уже проверено

- Production-like сборка: 16 публичных маршрутов на 320/390/1440 px; отдельная
  граница hero на 768/820/900/901/920 px. Page overflow, обрезанные контролы, битые
  изображения и не исчезающие skeleton не найдены.
- На маршрутах проверены scroll вниз/вверх; намеренные горизонтальные карусели
  и фильтры проверены вправо/влево, `scrollX` страницы остаётся нулевым.
- Добавлены regression-контракты motion/loading/404 и отдельный тест asset preload
  для 404. Финальный полный `npm run check` прошёл успешно: оба typecheck,
  все smoke/контрактные тесты, production build (2372 модуля, 27 маршрутов)
  и SEO-output 12/12. `git diff --check` также без ошибок.
- Скриншоты сравнения: `output/playwright/visual-fix/02-reference-vs-fixed.png`
  и `output/playwright/visual-fix/03-404-mobile-button-fixed.png`.

## Что осталось на следующий проход — сейчас не менять

1. Реальный iPhone/Safari: изменение адресной строки, touch inertia, поворот,
   возврат Back/Forward Cache, длительный scroll. Desktop Chromium viewport
   не доказывает отсутствие всех специфичных WebKit-композитных артефактов.
2. Повторяемые cold-cache Lighthouse/PageSpeed замеры всех URL на production и
   сверка с реальными Web Vitals. Один лабораторный score не считать гарантией.
3. Отдельно профилировать глобальный `motion` (~44 KiB gzip) и библиотеку
   `@font-face` в общем CSS. Не удалять их механически: motion задаёт reduced-motion,
   а библиотека нужна выбранным владельцем шрифтам и редактору.
4. Отдельная матрица всех авторизованных состояний админки, editor/preview,
   длинных статей/кейсов, диалогов, empty/error/loading-состояний. В этом пакете
   это не переобъявляется как выполненный полный построчный аудит всего проекта.
5. Продолжить по регламенту `DEEP-VISUAL-MOTION-AUDIT-PLAN.md`: читать связанные
   файлы целиком, фиксировать источник/потребитель/состояние, менять только
   подтверждённые ошибки и повторять mobile + desktop после каждого патча.

## Выкладка

Текущий пакет отправляется в `main` существующего GitHub → Cloudflare Pages
пайплайна. После push необходимо подтвердить новый hash production assets,
открыть Home/404/услуги в живом браузере и проверить основные scroll-сценарии.
Новые зависимости, плагины и альтернативные scroll-библиотеки в этом пакете
не устанавливались. Старые незакоммиченные PNG в `audit-reports/` не трогались.
