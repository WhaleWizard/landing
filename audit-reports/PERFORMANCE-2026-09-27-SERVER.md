## Находки

### S1 — ключ публичного кэша допускает бесконечные дубликаты — исправлено

`functions/api/articles.ts` игнорирует неподдерживаемые параметры, но строит Cache API key из полного `request.url`. Поэтому `?_=1`, `?_=2`, UTM и разный порядок параметров создают независимые записи и чтения D1. Очистка `buildSeoCacheTargets` удаляет только штатные URL; дубликаты могут переживать публикацию. Обход `cache=no-store` вдобавок возвращает cacheable Cache-Control.

В ключе остаётся только поддерживаемый `slug` либо `view=summary`, обход выдаёт `no-store`. Новый тест сначала воспроизвёл два чтения D1 на два запроса одного списка с разными `_`/UTM; после правки чтение одно. Detail с `view=summary` переиспользует точный detail key, сохраняет полный текст.

### S2 — ошибка загрузки HTML статьи маскируется статусом 200 — исправлено

`functions/_lib/article-page.ts` переписывал статус HTML shell на 200 независимо от успешности исходного asset response. Теперь 500/503 сохраняются. Если статья есть в CMS, но ещё нет ни её файла, ни исправного shell раздела, ответ временный: 503, no-store, Retry-After. Такой же временный ответ применяется к неправильному MIME вместо ложного 404/успешного text/plain. Ошибка Cache API у бота больше не обрывает чтение здоровой D1; UTM-параметры больше не дробят bot cache. Canonical redirects по-прежнему сохраняют query атрибуции.

### S3 — формы могли терять заявку или показывать ложную ошибку — исправлено

По согласованию с основным агентом проверены и изменены `ContactForm.tsx`, `LandingForm.tsx`, `utils/leadRetryQueue.ts`.

- Подготовка до HTTP (Turnstile, browser context, client IDs) была вне try/finally. Ошибка оставляла кнопку занятой. Теперь finally охватывает всю подготовку и отправку; незавершённый payload не попадает в очередь.
- Очередь глотала отказ localStorage, а формы стирали поля и обещали сохранение. `queueLeadForRetry` возвращает результат записи. При отказе поля остаются и форма честно сообщает, что отправка/сохранение не удались.
- После HTTP успеха ошибка хеширования/браузерного SDK попадала в общий catch отправки и могла поставить уже принятую заявку в очередь. Browser tracking теперь изолирован от результата HTTP, сохранив попытку сопоставления и тот же event_id. Успешный серверный приём продолжает вести на благодарность.

Девять новых поведенческих проверок исполняют настоящие submit callbacks с подставными браузерными зависимостями: ошибка подготовки, отказ storage, успешная offline очередь с прежним event_id/consent, отказ analytics после принятия сервером.

### S4 — лишний layout и React rerender при resize предпросмотра — исправлено

`AdminContentPreview.tsx` читал `clientWidth` и вызывал setState прямо из ResizeObserver. Теперь `previewViewportSizing.ts` использует готовый `entry.contentRect.width` и меняет только CSS переменные размеров/scale. Resize только по высоте больше не приводит к записи размеров; отступы учитываются по фактической внутренней ширине, в том числе на телефоне. Сам iframe, содержимое preview, протокол сообщений и сохранение текстов сохранены.

Дополнительно обнаружено: развёрнутый preview находится в Radix portal вне `.admin-root`, а стили stage/frame/iframe были ограничены `.admin-root`. `src/styles/admin-ui.css` применяет эти же правила и внутри `.admin-site-preview-dialog`.

Реальный браузер обнаружил по две ошибки `ResizeObserver loop completed with undelivered notifications` при открытии редактора. Запись размеров наблюдаемого stage из callback перенесена в requestAnimationFrame; callback только запоминает contentRect. Повтор всех четырёх ширин и обеих тем: 0 runtime ошибок, видимый iframe, ожидаемый scale. Regression отдельно запрещает CSS-записи до завершения observer delivery.

### S5 — блокировки забывались при двойном сбое хранилищ — исправлено

`readPageLockSnapshot` после истечения 30 секунд использовал только Cache API fallback, игнорируя прежнее успешное значение в памяти. При недоступных Cache API и D1 закрытая страница открывалась. Теперь выбирается самый свежий успешный снимок из обоих слоёв, его `savedAt` сохраняется. Отсутствующая миграция по-прежнему означает отсутствие блокировок. Regression проверяет отказ Cache API, D1 и затем отсутствие DB binding.

### S6 — мобильное окно предпросмотра уезжало за экран — исправлено

При 430 × 844 px окно получало координаты x = −215, y = −422: крестик находился выше экрана. Tailwind 4 использует отдельное свойство CSS `translate`, поэтому существующий `transform: none` не отменял сдвиг −50%. В мобильных стилях обоих Radix-диалогов (preview и библиотека шрифтов) добавлено `translate: none`. После исправления мобильный fullscreen начинается с (0, 0), кнопка доступна.

В общем `ui/dialog.tsx` точечно добавлены `forwardRef` для Overlay (реально воспроизведённое предупреждение React 18 из Radix SlotClone) и отсутствовавший `data-slot="dialog-close"` встроенному крестику. Последний включает уже существовавшие стили админки 44 × 44 px вместо 16 × 16. Контракт и структура Radix сохранены; изменение согласовано с основным агентом. После закрытия preview фокус возвращается на «На весь экран»; блокировка прокрутки снимается.

### S7 — мелкие поля в горизонтальной ориентации телефона — исправлено

На 844 px поиск блоков и абзацы редактора имели 14 px; существующий защитный стиль 16 px срабатывал только до 767 px. В конце admin-ui.css добавлен ограниченный админкой и её Radix portal стиль для coarse pointer и узкого экрана. Range/checkbox/radio/file/hidden исключены. При эмуляции coarse pointer проверены 18 разделов на 375 и 844 px: 36 состояний, все видимые текстовые поля не меньше 16 px, без переполнения документа и runtime ошибок.

## Уже проверенные гарантии

- Middleware пропускает проверку D1 для файлов, API и админки; блокировки имеют память на 30 секунд и резерв Cache API.
