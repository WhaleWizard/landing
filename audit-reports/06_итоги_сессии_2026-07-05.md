## 4. Аналитика — найденные и исправленные проблемы

- **Гео-фолбэк** (`requiresConsentByDefault()` в `consent.ts`) — задокументирован как намеренное бизнес-решение, трогать не нужно.
- **Обход `isTrustedTrackingRequest`** (`functions/_lib/meta-capi.ts`) — раньше запрос без Origin И без Referer считался доверенным. Теперь отклоняется.
- **Google Consent Mode v2** — добавлен (`setDefaultConsentState()` / `updateConsentState()` в `consent.ts`), раньше отсутствовал.
- **Retry-очередь для лид-форм** (`src/app/utils/leadRetryQueue.ts`, новый файл) — при потере сети заявка сохраняется в localStorage и уходит при восстановлении связи.
- **GA4 `client_id` / Yandex `clientID`** — добавлены в payload лида (`functions/api/lead.ts` + `getAnalyticsClientIds()` в `consent.ts`), доходят до CRM и Meta CAPI.
- **Санитайзер query-параметров** (`functions/_lib/url-sanitize.ts`, новый файл) — вырезает похожие на email/телефон/токен параметры из URL перед сохранением в CRM/диагностику.
- **⚠️ Главная находка: GA4 не получал вообще никаких данных.** Причина — `trackPageView()` в `consent.ts` вызывал `gtag('config', gaId, {page_path})` при смене SPA-роута. Это устаревший паттерн из Universal Analytics — в GA4 `gtag.js` он **не создаёт хит** на сервер Google. Из-за этого просмотры страниц (самое частое событие) физически никогда не долетали до Google, хотя в `dataLayer` всё выглядело корректно. Исправлено на `gtag('event', 'page_view', {...})`.
  - Важная оговорка: подтвердить фикс через автоматизированный браузер не удалось — Google и Meta детектят headless/automation-браузеры (даже с подделанным `navigator.webdriver`) и молча глушат сбор данных, тогда как Яндекс.Метрика в том же тесте бьёт нормально. Финальное подтверждение может дать только реальный человек в реальном браузере через GA4 Real-time — на момент конца сессии пользователь ещё не подтвердил успех со своего телефона.

## 5. SEO — структурные данные и trailing slash (`scripts/generate-pages.js`)

- **JSON-LD раньше существовал только в браузере** (клиентский `useEffect` в `SEO.tsx`) — не-JS краулеры (большинство AI-ботов) не видели вообще никакой структурной разметки на главной/услугах/FAQ/юридических страницах. Теперь `ProfessionalService` + `WebSite` схема вшиты прямо в статический HTML каждой генерируемой страницы. Главная страница вообще не имела JSON-LD ни в каком сценарии (не рендерила компонент `<SEO>`) — теперь имеет.
- `/faq` дополнительно получил `FAQPage` JSON-LD на все 41 вопрос-ответ.
- **Trailing slash**: Cloudflare отдаёт статические страницы только по адресу со слэшем (`/meta-ads` → 308 → `/meta-ads/`), а canonical/sitemap раньше указывали на адрес без слэша — получался редирект самого на себя. Поправили `canonical`/`og:url`/`sitemap.xml`, чтобы сразу указывать на реально отдаваемый адрес. `/blog/:slug` (обслуживается функцией, не редиректит) и файлы (`feed.xml`, `llms.txt`) оставлены без слэша.
- Добавлены build-time проверки в `validateGeneratedOutput()` — если JSON-LD или trailing slash пропадут в будущем, сборка упадёт сама.
