# Повторная проверка мобильных регрессий — 05.09.2026

Исходная версия: `c546df0` (production). Приоритет — мобильная загрузка и корректность интерфейса без изменения дизайна, ассетов, качества и задуманных анимаций.

## План и критерии

1. Воспроизвести линию поверх пунктов политики конфиденциальности: определить конкретный DOM-элемент, его scroll container и containing block. Проверить все четыре юридических документа в окне и отдельной страницей.
2. Снять свежие холодные mobile Lighthouse-замеры production. Отдельно разобрать загрузку HTML/CSS/JS/шрифтов/изображений, handoff и работу главного потока. Старые замеры не считать результатом текущей версии.
3. Прочитать цепочки общего визуального кода: bootstrap → маршруты → оболочка → shared motion/scroll → страницы/сцены; отмечать конкретные проверенные файлы и доказанные дефекты, не объявлять весь репозиторий проверенным по поиску шаблонов.
4. Исправлять подтверждённые причины минимально: сохранять внешность и эффекты; повторять воспроизведение после каждой связанной группы исправлений. Не добавлять библиотеку без измеримого выигрыша.
5. Проверить 320/390/453 px, tablet и desktop: верх/низ, обратный скролл, горизонтальный overflow; открытые окна/меню, аккордеоны, блокировку и восстановление фона, Escape/фокус. Не отправлять реальные заявки или рекламные тестовые события.
6. Выполнить `npm run check`, сравнить production-сборку локально, повторить сопоставимые холодные замеры. Выкладка — только после проверки; после неё подтвердить опубликованные ассеты и сценарии в живом браузере.

## Границы достоверности

- Эмуляция Chromium не является проверкой настоящего iOS WebKit. Показанный владельцем дефект требуется исправить по механизму, затем отдельно подтвердить на iPhone.
- Оценка Lighthouse — лабораторный замер; фиксировать параметры и фактические метрики, не обещать баллы заранее.
- Предыдущая проверка закрытых страниц не покрывала все состояния модалок. Это явный пробел, а не завершённый аудит.
