# Ускорение и исправления Whale Wizard — 27 сентября 2026

## Статус

Локальные изменения готовы и прошли полный `npm run check`, отдельный Meta CAPI smoke и проверки итоговой сборки в браузерах. На production изменения не отправлены. Основа изменений — commit `493fe6d`; рабочие правки пока не закоммичены.

Приоритет — мобильные экраны, сохранение композиции hero, картинок, рабочего редактора, SEO и аналитики. Новые зависимости приложения не добавлены.

## Что изменено

### Первый экран и нагрузка

- Главная получает настоящий Navbar и Hero уже в HTML сборки. Это те же React-компоненты и опубликованный CMS-текст, которые используются после запуска приложения. Промежуточная текстовая карточка убрана; при передаче управления React текст повторно не скрывается анимацией.
- Главные CTA стали настоящими ссылками на разделы: они работают и до загрузки JavaScript. Содержимое для поиска, canonical и JSON-LD сохранены.
- До запуска React фоновая анимация первого экрана приостановлена. Декоративные картинки загружаются с низким приоритетом; приоритет главного кита сохранён высоким.
- Шесть видимых сфер и кристаллов получают компактные WebP на экранах до 900 px. Размеры покрывают DPR 3, прозрачность сохранена; desktop использует исходные файлы. Скрытый на телефоне декор не скачивается.
- При создании клиентского DOM сразу задаётся правильный мобильный адрес img.src. Это предотвращает обнаруженную в WebKit дополнительную загрузку оригинала до подключения элемента к picture.
- Подгонка заголовков запоминает уже выполненный расчёт. Повторные таймеры и загрузка постороннего шрифта не запускают одинаковый поиск кегля. Изменения текста из CMS, используемого шрифта или ширины продолжают пересчитываться.
- Canvas декоративной пыли обновляется до 24 кадров/с на компактных экранах и до 60 на desktop. Скорость движения больше не зависит от частоты 120/144 Гц. Мобильный bitmap ограничен DPR 1.25; изображения hero сохраняют исходное качество.
- Сцены корректно останавливаются вне экрана, при прокрутке и в скрытой вкладке. Resize и переключение reduced motion не оставляют пустой canvas. Невидимые фоны перестали измерять геометрию при каждом движении мыши.
- У ноутбука и капсулы сохранены движение и постоянное свечение; дорогая пульсация фильтров упрощена.
- У кита уменьшен радиус двойной тени. Исходные 42/70 px ломали первый paint в WebKit при DPR 3; 16/20 px сохраняют силуэт, отделение от фона и свечение. Композиция и файл изображения не изменены.
- Commissioner использует общие URL для побайтово одинаковых файлов разных начертаний. Это устраняет повторные загрузки, сохраняя веса шрифта. Старые URL остаются доступными для совместимости.

### Страницы и мобильное управление

- Поиск/фильтры блога синхронизируются с адресом и историей браузера. Изменение query больше не переносит страницу наверх и не крадёт фокус у поля.
- Переход к связанному термину глоссария снимает фильтр, который скрывал этот термин.
- Ссылки и скачивание ZIP работают при первом открытии лениво загружаемого кейса; повреждённое кодирование имени файла не вызывает исключение.
- Карусель отзывов учитывает актуальное число карточек после загрузки CMS.
- Исправлены main-landmarks и перенос фокуса после загрузки следующей страницы. Действие пользователя отменяет ожидающий автоматический фокус.
- Ошибка старого чанка распознаётся также в Safari/Firefox; запрет sessionStorage больше не приводит к бесконечным перезагрузкам.
- Текстовые поля на touch-устройствах имеют 16 px, включая горизонтальную ориентацию. Desktop-типографика сохранена; исходных полей с кеглем выше 16 px в проверенном наборе не было.

### Формы, SEO и сервер

- Ошибки Turnstile/подготовки заявки освобождают кнопку отправки. При невозможности записать офлайн-очередь форма сохраняет введённые данные и сообщает об ошибке.
- Ошибка браузерной аналитики после успешного приёма заявки сервером больше не ставит уже принятую заявку в очередь повторной отправки. Исходный event_id сохраняется.
- API статей объединяет одинаковые запросы с разными UTM/служебными параметрами в один ключ кэша. Это уменьшает лишние чтения D1 и сохраняет корректность инвалидации. Ответы при обходе кэша теперь тоже содержат no-store.
- Ошибки 500/503 при загрузке HTML существующей статьи больше не маскируются статусом 200. Если HTML статьи отсутствует, используется исправная оболочка раздела. Если отсутствует и она либо получен неподходящий MIME, ответ — 503 с no-store и Retry-After; серверный 5xx оболочки сохраняется. Ошибка Cache API не блокирует чтение работающего источника.
- При одновременном отказе D1 и Cache API используется последний корректный список закрытых страниц, если он уже есть в памяти текущего обработчика.
- Consent, хеширование PII, дедупликация Pixel/CAPI и outbox не ослаблены. Прямые запросы к Meta и реальные заявки при аудите не отправлялись.

### Админка

- Предпросмотр больше не читает layout и не вызывает React setState из ResizeObserver. Запись размеров объединяется в один следующий кадр, что устраняет воспроизведённый ResizeObserver loop.
- Стили встроенного и развёрнутого iframe согласованы. Мобильные модальные окна предпросмотра и выбора шрифта корректно сбрасывают individual translate Tailwind 4 и остаются в viewport.
- У DialogOverlay исправлена передача ref для React 18/Radix. Крестик получил штатный data-slot для активной области 44 × 44 px. Закрытие возвращает фокус на кнопку открытия и снимает блокировку прокрутки.
- Протокол предпросмотра, структура CMS, вход/сессии/2FA и обработчики сохранения контента сохранены.

### Холодная загрузка: исходная и итоговая сборки

Один полный прогон до и один после: Chromium, CSS viewport 390/1440 × 900, DPR 1, CPU ×4, сеть 1.6 Мбит/с с задержкой 100 мс, отключённый кэш, одинаковый Vite preview и ответы API, окно наблюдения 9 секунд. Во время заключительного прогона другие проверочные браузеры были закрыты. Это лабораторная конфигурация; мобильная визуальная проверка DPR 3 выполнена отдельно.

**Ограничение:** desktop LCP главной в этом сравнении вырос на 424 мс. До компактных картинок промежуточный прогон также показывал ухудшение главной; дополнительные A/B дали основание снизить приоритет декора и приостановить SSR-анимации. Мобильный итог улучшился, но равномерное ускорение всех страниц и устройств не подтверждено. Абсолютные времена заметно менялись между прогонами, поэтому проценты общего ускорения по этим данным не заявляются. Desktop-главная остаётся пунктом контроля на Cloudflare и по реальным Web Vitals после выкладки.

Исходные данные: `output/playwright/performance-2026-09-27/baseline/metrics.json` и `final-compact/metrics.json`, полное сравнение FCP/LCP/CLS/ресурсов — `final-compact/comparison.json`. Промежуточный набор `final/` использовал другой HTTP-стенд и исключён из сравнения скорости; он пригоден только для диагностики своего запуска.

## Что требует проверки на живом сайте

1. Production-админка потребовала второй фактор. После входа владельца проверить живые данные D1/R2, сохранение и публикацию тестовой правки с последующим возвратом.
2. После выкладки проверить доставку/дедупликацию в диагностике Meta и Events Manager. Локальные smoke-тесты не подтверждают внешний ответ Meta.
3. Проверить несколько физических iPhone в Safari, особенно прокрутку, клавиатуру и изменение высоты адресной строки. Здесь использованы Chromium и WebKit на Windows с мобильными параметрами, включая DPR3.
4. Сравнить реальные Core Web Vitals после накопления трафика. Локальная симуляция не заменяет данные посетителей и сеть Cloudflare.

Публичные браузерные матрицы использовали production-сборку и явно подставленные ответы API. Локальная админка проверена на Vite без сохранения данных: с реальными локальными пустыми/недоступными разделами, доступным снимком контента и вводом пробного текста в preview. Запросы записи в admin API, кроме входа, дополнительно блокировались браузерным guard. Это не проверка всей production-базы.
