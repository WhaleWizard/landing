# Этап 0: код под 600 статей — проект и статус

Проект написан по картам кода (пять читателей) и реализуется пакетами. Каждый пакет заканчивается
тестами, `npm run check`, коммитом и выкладкой. Статус помечен прямо здесь.

Ограничения, которые держим везде: внешний вид публичных страниц не меняется; числа не выдумываем;
раздел без миграции объясняет себя (`MIGRATION_REQUIRED`); D1 бесплатный, записи экономим;
`publishedAt` — дата первой публикации; слаги не меняются; три санитайзера согласованы.

---

## Пакет 1 — сохранение статьи по одной ✅ (23.09.2026)

Проблема: админка слала весь блог одним запросом при лимите тела 256 КБ; 13 статей = 168 КБ.

Контракт: `PATCH /api/admin/articles`, тело `{ article }`, заголовок `X-Admin-Password`.
Ответ `{ success, article, created }`. Upsert по слагу: id новой статьи выдаёт сервер
(`MAX(id)+1`), соседи не трогаются, ничего не удаляется. Защита опорной статьи — как в PUT.
Кэш чистится точечно (список, sitemap, feed, страница статьи), IndexNow пингует только видимое.
Снимок D1 в R2 пишется в фоне после записи. Режим списка (PUT) остался для удаления и порядка.

Файлы: `functions/_lib/d1.ts` (`writeArticleToD1`, `nextArticleIdFromD1`), `functions/_lib/articles.ts`
(`persistD1ArticlesSnapshot`), `functions/api/admin/articles.ts` (`onRequestPatch`),
`src/app/components/hooks/useArticlesApi.ts` (`saveArticle`), `src/app/context/ArticlesContext.tsx`
(`updateArticle`), `src/app/pages/Admin.tsx` (`handleSave`).
Импорт: `npm run import:articles -- --dir <папка> --env-file <путь>`; JSON-статьи, статус по умолчанию
черновик, пауза под лимит 30 запросов в минуту. Тест: `scripts/admin-article-save.test.js` на SQLite.

## Пакет 2 — админка без полного текста ✅ (23.09.2026)

- `GET /api/admin/articles?view=summary` — список без `content`, с черновиками и запланированными.
- `GET /api/admin/articles?slug=<slug>` — одна статья целиком, включая черновики.
- `DELETE /api/admin/articles?slug=<slug>` — удаление одной; версии остаются. Через PUT списка
  удалять больше нельзя: список без текстов затёр бы тела соседей.
- Клиент: `fetchAdminArticles` → краткий вид; `fetchAdminArticle(slug)`; `deleteArticle(slug)`.
  В админке `openArticleForEdit` догружает текст по слагу перед открытием редактора; дубликат тоже.
  Перетаскивание порядка убрано — его заменило закрепление (пакет 3).
- Общие функции очистки кэша вынесены в `functions/_lib/article-cache.ts`.

## Пакет 3 — закреплённые на главной ✅ (23.09.2026)

- Миграция `0042_articles_featured_order.sql`: колонка `featured_order` и частичный индекс.
  Карта миграций пересобрана, описание — в `migration-unlocks.ts`. **Применяет владелец.**
- `Article.featuredOrder`; `d1.ts` читает и пишет колонку только если она есть; обычное сохранение
  статьи закрепление не снимает (`COALESCE`), снимает только эндпоинт закрепления.
- `PUT /api/admin/articles-featured` `{ slugs }` — перечисленным 1..N, остальным пусто, одним batch.
  Без миграции — `503 MIGRATION_REQUIRED`, раздел «Миграции» покажет 0042 следующей.
- Правило показа общее для `Blog.tsx` и генератора — `src/app/utils/homeArticles.ts`:
  закреплённые по порядку (до 15), иначе 15 последних по дате; кейсы не попадают.
  Встроенный seed главной — ровно этот список, а не весь блог.
- Админка: кнопка-булавка «на главной» на месте ручки перетаскивания, бейдж с номером и стрелки
  порядка среди закреплённых. Кейсы закрепить нельзя.
- Тесты: `scripts/admin-article-save.test.js` (11 сценариев на настоящем SQLite, включая ответ
  без миграции).

Замечание по кэшу колонок: `getArticlesColumns` помнит схему пять минут. После применения 0042
закрепление начинает работать сразу (эндпоинт не зависит от кэша), а обычное сохранение статьи
учитывает колонку с задержкой до пяти минут — на данные это не влияет.

## Пакет 4 — блог на 600: страницы, поиск, сортировка ✅ (23.09.2026)

- Страницы по 24 на клиенте с кнопкой «Показать ещё», состояние в URL: `?search=&topic=&sort=&page=`.
- Сортировки: новые, старые, короткие (по времени чтения); раздел — фильтром, а не сортировкой.
  Поиск по заголовку, описанию, тегам, разделу — по кратким записям, без текста.
- Статический `/blog` для роботов: список ссылок на все статьи остаётся полным (каждая статья в одном
  переходе от раздела), встроенный seed — первые 24. Проверка в генераторе считает seed по маршруту,
  а не «все статьи везде». Страницы `?page=N` — канонический адрес `/blog/`, без отдельной индексации.

## Пакет 5 — расписание публикаций ✅ (23.09.2026)

- Механизм уже был: статья со статусом `published` и `publishedAt` в будущем невидима до срока
  (`isPublishedArticle`), страницы статей отдаёт Functions без пересборки. Публичный список живёт
  в кэше две минуты — на столько статья может опоздать.
- Панель «Расписание публикаций» под календарём (`PublishSchedulePanel.tsx`): черновики и уже
  запланированные галочками, начало, дней, статей в день, окно часов, случайный порядок.
  Расчёт — чистая функция `src/app/utils/publishSchedule.ts`: пояс Asia/Tashkent (+05:00, без
  перевода часов), зазор между статьями дня не меньше 45 минут, первая статья — в день начала,
  при нехватке мест лишние возвращаются списком, а не теряются. Тесты — `test:publish-schedule`.
- Сохранение одним запросом `PUT /api/admin/articles-schedule` (до 200 за раз): меняются только
  статус и дата выхода, текст не трогается. Уже вышедшие статьи и опорная пропускаются — их дату не
  сдвигают. Перераспределить — та же панель по тем же статьям.
- Попутно найдена и исправлена авария из пакета 2: после снятия перетаскивания со списка у
  редактора статьи пропал контекст react-dnd, и открытие любой статьи роняло админку. Редактор
  теперь сам оборачивает себя в `DndProvider`; `test:audit-regressions` ловит любой компонент
  с `useDrag`/`useDrop` без своего провайдера.

## Пакет 6 — картинки без пересборки ✅ (23.09.2026)

- Копии делает браузер при загрузке (`utils/prepareImageUpload.ts`, заменил
  `compressImage`): оригинал — WebP до 2200 px, копии 480/768/1200/1600. Соглашение имён уточнено:
  размеры оригинала пишутся в имя (`…--<Ш>x<В>.webp`, копия `…--<Ш>x<В>-<ширина>.webp`), чтобы
  странице хватало адреса и для `srcset`, и для `width`/`height` — без манифеста и без запроса к R2.
  Сервер принимает копии только полным набором и пишет оригинал последним. Медиатека копии
  прячет, переносит и удаляет вместе с оригиналом. Тесты — `test:image-variants` (12).
- Уже закоммиченные файлы в `public/images/articles` не трогаем: они обслуживают старые адреса.
- Замечание для владельца: публичный адрес `pub-….r2.dev` Cloudflare считает адресом для
  разработки — он не кэшируется на CDN и ограничен по частоте. При росте трафика стоит подключить
  к бакету свой поддомен (например, `media.whalewzrd.com`) в панели R2 и задать его в
  `R2_PUBLIC_HOST`; код уже распознаёт копии на доменах сайта.

## Пакет 7 — восемь разделов ✅ (23.09.2026)

- Один справочник разделов (`src/app/data/blogSections.ts`): Реклама в Instagram и Facebook ·
  Приложения · Google Ads · Ниши · Деньги и окупаемость · Аналитика и трекинг · Как выбрать
  подрядчика · Кейсы, с сопоставлением старых категорий. Редактор предлагает разделы списком,
  фильтр блога опирается на него. Кейсы по-прежнему определяет `isCaseArticle()`.
- Сделано: у статьи ровно один раздел (раньше тема угадывалась по словам, и одна статья числилась
  в четырёх темах). Полное название хранится в `category`, на плитке и карточке — короткое
  («Instagram и Facebook», «Окупаемость»), описания плиток до 28 знаков, чтобы не обрезаться на
  320 px. Старые категории показываются как были, старый адрес `?topic=growth` ведёт в «Окупаемость».
- Редактор: новая статья без раздела не сохраняется; у старой статьи её категория видна отдельным
  пунктом с подсказкой, к какому разделу она относится. `import:articles` отклоняет статью
  с разделом не из справочника. Тесты — `test:blog-sections` (7).
