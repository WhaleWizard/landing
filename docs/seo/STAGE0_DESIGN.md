# Этап 0: код под 600 статей — проект и статус

Проект написан по картам кода (пять читателей) и реализуется пакетами. Каждый пакет заканчивается
тестами, `npm run check`, коммитом и выкладкой. Статус помечен прямо здесь.

Ограничения, которые держим везде: внешний вид публичных страниц не меняется; числа не выдумываем;
раздел без миграции объясняет себя (`MIGRATION_REQUIRED`); D1 бесплатный, записи экономим;
`publishedAt` — дата первой публикации; слаги не меняются; три санитайзера согласованы.

---

## Пакет 1 — сохранение статьи по одной ✅ (23.09.2026)

Проблема: админка слала весь блог одним запросом при лимите тела 256 КБ; 13 статей = 168 КБ.

Контракт: `PATCH /api/admin/articles`, тело `{ article }`, заголовок `X-Admin-Password`.
Ответ `{ success, article, created }`. Upsert по слагу: id новой статьи выдаёт сервер
(`MAX(id)+1`), соседи не трогаются, ничего не удаляется. Защита опорной статьи — как в PUT.
Кэш чистится точечно (список, sitemap, feed, страница статьи), IndexNow пингует только видимое.
Снимок D1 в R2 пишется в фоне после записи. Режим списка (PUT) остался для удаления и порядка.

Файлы: `functions/_lib/d1.ts` (`writeArticleToD1`, `nextArticleIdFromD1`), `functions/_lib/articles.ts`
(`persistD1ArticlesSnapshot`), `functions/api/admin/articles.ts` (`onRequestPatch`),
`src/app/components/hooks/useArticlesApi.ts` (`saveArticle`), `src/app/context/ArticlesContext.tsx`
(`updateArticle`), `src/app/pages/Admin.tsx` (`handleSave`).
Импорт: `npm run import:articles -- --dir <папка> --env-file <путь>`; JSON-статьи, статус по умолчанию
черновик, пауза под лимит 30 запросов в минуту. Тест: `scripts/admin-article-save.test.js` на SQLite.

## Пакет 2 — админка без полного текста

- `GET /api/admin/articles?view=summary` — список без `content` (D1: `fetchArticleSummariesFromD1`;
  JSONBin: срезать поле). Черновики и будущие даты включены — это админка.
- `GET /api/admin/articles?slug=<slug>` — одна статья целиком, включая черновики.
- `DELETE /api/admin/articles?slug=<slug>` — удаление одной. Версии не трогаем.
  Нужен, потому что удаление через PUT списка из кратких записей затёрло бы тексты пустыми строками.
- Клиент: `fetchAdminArticles` → summary; `fetchAdminArticle(slug)`; `deleteArticle(slug)`.
  `openArticleEditor` сначала догружает текст по слагу, потом открывает редактор.
  Перетаскивание порядка убирается — его заменяет закрепление (пакет 3).

## Пакет 3 — закреплённые на главной

- Миграция `0042_articles_featured_order.sql`: `ALTER TABLE articles ADD COLUMN featured_order INTEGER;`
  плюс частичный индекс по непустым значениям. После добавления — `npm run build:migration-map`
  и строка в `functions/_lib/migration-unlocks.ts`.
- `Article.featuredOrder?: number | null`; чтение и запись в `d1.ts` только если колонка есть
  (`getArticlesColumns`); `normalizeArticles` пропускает поле; краткий вид отдаёт его наружу.
- `PUT /api/admin/articles-featured` `{ slugs: [...] }` — одним batch: перечисленным 1..N, остальным NULL.
  Без миграции — `503 MIGRATION_REQUIRED` через `migration-guard`.
- Правило показа (одно и то же в `Blog.tsx` и в `generate-pages.js`): если есть закреплённые —
  они по `featuredOrder`, не больше 15; иначе 15 последних по дате публикации, без кейсов.
  Встроенный seed главной — ровно эти 15, а не весь блог.
- Админка: у строки списка галочка «На главной» и стрелки порядка среди закреплённых; сохранение —
  одним запросом на новый порядок.

## Пакет 4 — блог на 600: страницы, поиск, сортировка

- Страницы по 24 на клиенте, состояние в URL: `?search=&topic=&sort=&page=`.
- Сортировки: новые, по разделу, по времени чтения. Поиск по заголовку, описанию, тегам, разделу —
  по кратким записям, без текста.
- Статический `/blog` для роботов: список ссылок на все статьи остаётся полным (каждая статья в одном
  переходе от раздела), встроенный seed — первые 24. Проверка в генераторе считает seed по маршруту,
  а не «все статьи везде». Страницы `?page=N` — канонический адрес `/blog/`, без отдельной индексации.

## Пакет 5 — расписание публикаций

- Механизм уже есть: статья со статусом `published` и `publishedAt` в будущем невидима до срока
  (`isPublishedArticle`), страницы статей отдаёт Functions без пересборки. Нужны: панель в админке
  и проверка TTL кэша публичного списка, чтобы статья появлялась не позже чем через несколько минут.
- Панель «Расписание» в разделе статей: выбрать черновики (галочками или «все»), начало, дней,
  статей в день, окно часов; кнопка раскладывает случайные слоты в поясе Asia/Tashkent (+05:00, без
  перевода часов) и сохраняет каждую статью через PATCH с паузой под лимит; прогресс виден.
  Календарь публикаций показывает план. Перераспределить — та же кнопка по тем же статьям.

## Пакет 6 — картинки без пересборки

- Варианты делаются в браузере при загрузке (в админке уже есть `compressImage`): к оригиналу
  добавляются WebP 480/768/1200/1600 и кладутся в R2 рядом по соглашению имён
  `<имя>.<ширина>.webp`. `articleImages.ts` выводит `srcset` по этому соглашению для адресов R2,
  для внешних адресов (ImgBB) остаётся манифест сборки. Тест `article-images` сохраняется.
- Уже закоммиченные файлы в `public/images/articles` не трогаем: они обслуживают старые адреса.

## Пакет 7 — восемь разделов

- Один справочник разделов (`src/app/data/blogSections.ts`): Реклама в Instagram и Facebook ·
  Google Ads · Приложения · Аналитика и трекинг · Деньги и окупаемость · Ниши · Как выбрать
  подрядчика · Кейсы, с сопоставлением старых категорий. Редактор предлагает разделы списком,
  фильтр блога опирается на него. Кейсы по-прежнему определяет `isCaseArticle()`.
