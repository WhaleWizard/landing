# Коммерческое SEO Whale Wizard

## Карта посадочных

Это рабочие группы запросов. Их спрос и позиции проверяем по данным Search Console в нужных странах.

| URL | Что ищет клиент | Что должно помочь принять решение |
|---|---|---|
| `/` | Таргетолог Instagram и Facebook, специалист по Google Ads | Кто ведёт проект, какие задачи берёт и какую услугу открыть |
| `/meta-ads/` | Настройка и ведение рекламы в Instagram и Facebook, таргетолог для онлайн-школы | Как проходит запуск, что считаем по CRM, какой опыт можно показать |
| `/meta-apps/` | Продвижение мобильных приложений в Meta Ads под ключ, реклама iOS и Android | Что подготовить, какие события доступны, как оценить тест и дальнейшее ведение |
| `/google-ads/` | Настройка и ведение Google Ads, контекстная реклама под ключ | Как проверяем спрос и выбираем между Поиском, Shopping и Performance Max |
| `/consult/` | Консультация таргетолога, аудит рекламного кабинета | Что входит, что подготовить и какой план клиент получает |

Для пилота берём Meta Apps и онлайн-образование. Добавляем полноценный кейс, когда подтверждены данные и разрешение на публикацию. Статья помогает оценить задачу, кейс показывает практический результат, посадочная объясняет условия работы и ведёт к форме. Решение об отдельной странице онлайн-образования принимаем после проверки спроса и материалов.

## Что сделать владельцу

1. Открыть Google Search Console и выбрать ресурс домена `whalewzrd.com` или URL-префикс `https://www.whalewzrd.com/`. В **Файлы Sitemap** проверить, что `https://www.whalewzrd.com/sitemap.xml` принят. Если его там нет, отправить. В **Проверка URL** посмотреть главную и четыре посадочные из таблицы. Важны статус индексации и канонический URL, выбранный Google.
2. В **Эффективность → Результаты поиска** выбрать тип поиска «Веб», период «Последние 3 месяца» и выгрузить Excel или CSV. Приложить также выгрузку **Индексирование → Страницы**. Если экспорт недоступен, достаточно скриншотов статусов sitemap и проверок URL. Для разбора коммерческих запросов указать приоритетные страны. В выгрузке «Результаты поиска» полезно дополнительно открыть каждую из двух приоритетных посадочных фильтром страницы и экспортировать её запросы.
3. Для автоматического отчёта включить **Google Search Console API** в Google Cloud. В **IAM и администрирование → Сервисные аккаунты** создать отдельный аккаунт, затем в **Ключи → Добавить ключ → Создать новый ключ** выбрать JSON. В **Search Console → Настройки → Пользователи и разрешения** добавить email аккаунта с ограниченным доступом для чтения отчётов.
4. В **Cloudflare → Workers & Pages → проект сайта → Settings → Variables and Secrets** выбрать **Production** и создать секрет `GSC_SERVICE_ACCOUNT_JSON`. Вставить полный JSON. Для доменного ресурса используется `sc-domain:whalewzrd.com`. Если выдан доступ к ресурсу с URL-префиксом, создать переменную `GSC_PROPERTY` с точным префиксом, включая конечный слеш. После новой production-выкладки открыть **Админка → SEO и Поиск → Обновить**. Статус «Данные Google получены» означает, что API ответил успешно. JSON-ключ хранится в секретах Cloudflare.
5. Для отчёта по заявкам открыть **Админка → Миграции** и убедиться, что `0045_google_organic_landing.sql` ожидает применения. В **Cloudflare → D1 → рабочая база → Console** выполнить один запрос из блока ниже. Затем обновить **Миграции** и открыть **Воронка → Посадочные из Google Поиска**. Исторические заявки останутся без этой атрибуции. Новые попадут в отчёт при согласии на маркетинг и распознанном входе из Google. При повторной заявке используется источник последней заявки контакта.
6. Прислать по одному примеру проекта для Meta Apps и онлайн-образования. Достаточно ответить голосом или текстом. Нужны ниша, рынки, период, что сделали, какие метрики и цифры можно подтвердить, какие скриншоты можно показать, можно ли назвать клиента. Показатели приложения и школы оцениваем в контексте их задач, бюджетов и периода. Прислать можно только те данные, которые разрешено публиковать.

```sql
ALTER TABLE leads ADD COLUMN google_organic_landing_path TEXT NOT NULL DEFAULT '';
```

Яндекс Вебмастер проверяем отдельно, когда он нужен для приоритетных рынков. Доступ владельца и принятый sitemap смотрим в самом кабинете.

## Как оценить результат

- После выкладки подтвердить заголовки, canonical и ссылки на живом сайте. Через Search Console проверить, какую версию Google проиндексировал.
- Сравнить два сопоставимых периода по одному набору коммерческих запросов, посадочных, стран и устройств. Разделять брендовые запросы Whale Wizard и запросы на услуги.
- По приоритетным URL сверять показы, клики и CTR с целевыми заявками и выигранными сделками. Данные Search Console агрегированы. Заявку оцениваем по посадочной, связать её с отдельным поисковым запросом по этим данным нельзя.
- Если у страницы есть релевантные показы и слабый CTR относительно похожих запросов, проверить выдачу и заголовок. Если есть целевые клики и мало заявок, проверить оффер, доказательства и путь к форме. Для страниц с малой выборкой собрать больше данных.
- Полевые LCP, INP и CLS смотреть в Search Console или PageSpeed Insights при наличии данных. Lighthouse использовать как лабораторную диагностику.

## После сбоя или восстановления

Проверить главную, четыре услуги, свежую статью, sitemap, robots и настоящий 404. Сопоставить даты публикаций с последней рабочей версией. Проверить D1 и медиа R2. Владелец отправляет тестовую заявку и проверяет, что она записалась в CRM и дошла в Telegram. Для страниц, которые выпали из индекса, посмотреть причину в Search Console и после восстановления запросить переобход. Зафиксировать дату резервной копии и проверку восстановления вне рабочей базы.
