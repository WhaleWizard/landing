## Исправление PA-01…03

Расчёт вынесен в `adminUnitEconomics.ts`. Некорректный ввод даёт пояснение, без результатов/экспорта и NaN. Ползунки согласованы с дробными значениями всех пресетов. Расчёт не округляет CPL перед вычислением CAC; небольшие бюджеты сохраняют центы. Предельные цены округляются вниз, чтобы не обещать целевой ROMI выше фактического. Прогнозный CPL и верхняя цена для ROMI 150% разделены. Убыточный экспорт больше не называет модель устойчивой только из-за высокого LTV. «Чистая прибыль» уточнена до «Прибыль после рекламы»: другие расходы и налоги не переданы в эту модель.

Базовый пример: 10000 / 1200 → 9 продаж, 50 лидов, 1250 кликов, бюджет 1500, выручка 10800, валовая прибыль 7020, после рекламы 5520, ROMI 368%, ROAS 7,2. Независимые ожидания закреплены тестом. Локально также проверены нулевой план и убыточный сценарий CPC=6: −480, ROMI −6%, порог CPC 5,61.

Шесть новых регрессионных сценариев включены в существующие test:calculator и test:audit-admin-crm-ui. Полный npm run check завершён с кодом 0: `output/admin-production-acceptance-2026-10-30/full-check.log`, отдельный `.exit` = 0. На production повторены нулевой/обычный/убыточный сценарии и совпадение ползунка 1200 с полем 1200.
