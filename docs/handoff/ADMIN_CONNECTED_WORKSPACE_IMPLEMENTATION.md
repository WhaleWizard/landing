## Правила реализации

Клиент — общая сущность. Проект — постоянная/сложная работа; разовая услуга имеет компактный сценарий и не требует большого проекта. Предложенная услуга не равна заказанной, выставленный счёт не равен полученным деньгам. Частичные поступления и их даты — единый источник финансовых сводок. Разные валюты отдельно. Общие данные клиента не копировать в каждый проект.

Обновлять этот файл по мере результатов. Базовые документы/пример: ADMIN_CONNECTED_WORKSPACE_PROPOSAL.md.

### Подключение базы владельцем

1. После выкладки открыть Админка → Миграции. Должна появиться только новая 0044_connected_workspace.sql.
2. В Cloudflare открыть D1 базу, привязанную к Pages как DB; перед изменением сохранить резервную копию/точку восстановления.
3. Скопировать SQL только миграции 0044 кнопкой в админке и применить её один раз в консоли этой базы. Не запускать старые миграции повторно. Исходник: migrations/0044_connected_workspace.sql. При ошибке остановиться и передать текст ошибки: повтор ALTER TABLE вслепую недопустим.
4. Обновить Миграции: ожидается 44/44, без частичных. Затем открыть Проекты, Клиенты и Финансы. Исторические счета не распределяются по проектам автоматически.

Откат интерфейса возможен предыдущим коммитом cc6a07c; новые таблицы/историю поступлений не удалять. После первой частичной оплаты откат финансовой логики требует отдельной сверки, поскольку старый интерфейс не представляет частичные поступления. Production-записи для тестов не создавать.
