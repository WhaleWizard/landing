# Как продолжить: третья волна аудита и остаток по скорости

Файл написан 02.10.2026 в конце облачной сессии, когда кончались кредиты. Владелец сказал:
«вторую волну доделай, третью продолжу потом». Здесь — ровно то, с чего начинать, без разбега.
Общий контекст проекта — `CLAUDE.md`, состояние и очередь — `docs/handoff/README.md`.

## 1. Что уже на проде и в ветке

- Ветка `claude/laughing-archimedes-unb9fp` слита в `main` быстрой перемоткой; Cloudflare Pages
  выкладывает `main` сам. В прод ушли: ускорение сайта (`docs/handoff/SPEED_PLAN.md`), серверные
  группы аудита и их стыки, вторая волна (интерфейс админки: оболочка и статьи, CRM и финансы, редактор).
- Если в `git log main` последний коммит ещё «wip(audit)…» или «fix(audit): стыки серверных групп» —
  значит вторая выкладка не дошла: взять ветку, прогнать `npm run check`, и `git push origin <sha>:main`.

## 2. Третья волна: группы routing, blog, forms, seo-build (46 открытых находок)

Команда (один запуск = одна волна; группы можно давать по одной, так дешевле и безопаснее при обрыве):

```
Workflow({ name: 'audit-fix', args: { groups: ['routing', 'blog'], waveSize: 2 } })
Workflow({ name: 'audit-fix', args: { groups: ['forms', 'seo-build'], waveSize: 2 } })
```

Сценарий — `.claude/workflows/audit-fix.js`: сверка с кодом → правка → независимое ревью → доработка →
учёт статусов (он сам правит `audit-findings.json`, `FIX_PLAN.md`, `package.json`). Ориентир по цене:
вторая волна из трёх групп (44 находки) стоила около 2,2 млн токенов исполнителей — примерно 40–50 $.
Группа `forms` трогает трекинг и согласие: после неё обязательно `npm run test:meta-capi` и production-сборка.

После каждой волны руками (сценарий этого не делает):

1. Строки новых тестов — в таблицу `npm run check` в `CLAUDE.md` и `AGENTS.md` (зеркала).
2. `npm run check` целиком. Тесты статей первого экрана берут `data/articles.local.json`, если снимка
   сборки ещё нет — на свежей копии это нормально.
3. Коммит, push ветки, затем `git push origin <sha>:main` — выкладка.
4. Стыки, которые волна записала в `docs/handoff/FIX_PLAN.md` → «Стыки между группами», закрыть отдельным
   исполнителем (как сделано 02.10 для серверных стыков: `docs/handoff/work/fix-cross-group.md`).

## 4. Остаток по скорости (`docs/handoff/SPEED_PLAN.md`)

- Списки `/blog` и `/cases`, FAQ, калькуляторы, юридические страницы пока монтируются поверх текстовой
  оболочки (карточка «Загружаем…» 1–2 с при холодном открытии). Следующий кандидат — списки блога и кейсов по
  образцу статей (`scripts/ssr-entry.tsx`, `renderRoute`). Подводный камень: `CasesPage` разбирает фильтры из
  адреса в эффекте (`urlReady`), серверный рендер дал бы скелет — сначала перенести разбор в начальное
  состояние из `location.search`. Гидратацию включать только без параметров в адресе.
- C4: библиотека шрифтов CMS (152 КБ `@font-face`) в блокирующей таблице — выигрыш десятки миллисекунд, низкий
  приоритет.
- Стенд замеров — `scripts/perf-lab/README.md`.
