# План «Сайт летает»: первая загрузка без мигания, плавность на всех страницах

Дата: 06.10.2026. Источник решения: владелец — «мне нужно, чтобы летала и была идеальная плавность
и отображение с первой загрузки на всех страницах, особенно на основных». Приоритет над статьями.
Правила неизменны: вид и анимации не меняются (`docs/DESIGN_LOCK.md`), Meta CAPI и согласие
неприкосновенны, цифры не выдумываем. Этот файл — живой: находки по ходу дописываются в раздел 9,
статусы — в чекбоксы. Точка входа для продолжения — `docs/handoff/README.md`.

Что грузит главная на телефоне: 24 JS-файла (197 КБ сжатых), 3 CSS (32 КБ сжатых, из них

маленькие файлы приходят к 0,5 с, крупные (`vendor` 77 КБ, `motion` 33 КБ) — к 1,33 с, затем пауза,
и cookie-баннер с согласием стартует только в 1,9–2,1 с. До этого момента посетитель видит картинку,
но кнопки, меню и формы не отвечают.

Что видно глазами (мигание): на `/blog/`, `/cases/`, `/faq/`, `/marketing-glossary/`, `/calculator/`,
`/roi-calculator/`, `/offer/`, `/privacy-policy/`, `/cookie-policy/`, `/thank-you/` сначала рисуется
одноцветная карточка с заголовком и строкой «Загружаем интерактивную версию сайта…», через 0,3–1,5 с
её сносит и ставится настоящая страница. На кейсах первый экран правильный, но React не принимает
готовую разметку (нет данных кейса в сборке) и перестраивает страницу заново — текст прыгает.

Сервер: TTFB 0,12–0,46 с (норма для Cloudflare из Ташкента), HTML не кэшируется на CDN
(`max-age=0, must-revalidate`), `/assets/*` — год и `immutable` (правильно), API статей — 2 минуты.

## 1. Цель в измеримых словах

На каждой публичной странице, с первой холодной загрузки на телефоне:

1. Первый кадр — уже настоящий дизайн страницы, никаких промежуточных карточек и скелетонов (кроме
   контента, которого на сборке нет: живые списки догружаются поверх готовой разметки без сдвигов).
2. Ни одного сдвига вёрстки (CLS 0) и ни одной перерисовки готовой разметки при оживлении
   (в консоли нет «hydration fell back to client render»).
3. Страница отвечает на нажатие не позже чем через ~1 с после прихода HTML на средней 4G
   (сейчас на главной 2,3 с).
4. Прокрутка и анимации — 60 к/с на iPhone 11 и новее: нет длинных задач на главном потоке после
   загрузки, анимации на композиторе (transform/opacity или CSS), а не на JS.
5. Переходы внутри сайта — мгновенные: следующая страница подготовлена заранее (по наведению,
   по касанию, по появлению ссылки на экране), контент приходит из кэша.
6. Вес первой загрузки главной на телефоне: JS ≤ 120 КБ сжатых на критическом пути,
   блокирующий CSS ≤ 20 КБ сжатых, картинки первого экрана ≤ 200 КБ.

Проверка — не Lighthouse на стенде, а: (а) настоящий Chrome в режиме iPhone с замедлением ×4 через
встроенный браузер на production, (б) реальные Core Web Vitals посетителей в админке «Скорость»
(таблица `web_vitals_daily`) до и после, (в) трассировка «HTML → React» без расхождений.

## 3. Пакет B — интерактивность за секунду (критический путь JS)

- [ ] B1. Водопад JS: 24 файла ступенями до 1,33 с. Причины: `modulepreload` на 20 мелких чанков
  (по 0,3–9 КБ) + крупные `vendor`/`motion` стартуют вместе с ними и доезжают последними.
  Решение: объединить мелкие чанки маршрута в один (manualChunks по маршруту: `route-home`,
  `route-service`, `route-blog`…), общие утилиты — в `vendor`; цель — ≤ 8 запросов JS на первый
  экран. Проверить, что HTTP/2-приоритеты Cloudflare не ломают порядок (preload критичных первыми).
- [ ] B2. `vendor` 237 КБ несжатых (77 сжатых): React 18 + react-dom + react-router 7 + scheduler.
  Оценить: (а) обновление на React 19 — меньше и быстрее гидратация, селективная гидратация по
  приоритету; риск — motion/radix совместимость, проверить; (б) если нет — хотя бы не тянуть
  `react-router` целиком (data APIs не используются?).
- [ ] B3. `motion` 91 КБ несжатых (33 сжатых) на главной: `LazyMotion(domAnimation)` уже есть, но
  чанк `motion` грузится как есть. Проверить, что в него попадает (`domAnimation` ≈ 15 КБ, остальное —
  `MotionConfig`, `m`, утилиты). Вынести редкие возможности (layout-анимации, drag) из первого экрана.
- [ ] B4. Cookie-баннер, согласие и пиксели стартуют отдельной волной в 1,9 с — после всего. Это
  правильно для трекинга (не на критическом пути), но баннер должен появляться **сразу после первого
  кадра**, а не через две секунды: вынести баннер из цепочки «после загрузки маршрута» в
  `requestIdleCallback` после первого коммита, его чанк — в modulepreload.
- [ ] B5. `contentTypography` 32 КБ на главной ради подгонки заголовка: для гидратируемых страниц
  кегль уже посчитан `title-prefit` — хук должен брать готовый результат и не тащить алгоритм
  до первого взаимодействия (ленивый импорт при повороте экрана/ресайзе).
- [ ] B6. `select` 69 КБ (radix select + cmdk?) — проверить, на каких публичных страницах грузится;
  публичные `AdminSelect`-подобные элементы не должны тянуть radix на главную.
- [ ] B7. `SEO.tsx` на критическом пути первого экрана: мета-теги уже в HTML из сборки; на
  гидратируемых страницах компонент может подключаться после первого коммита.
- [ ] B8. Проверить `prepareRoute` + таймаут 8 с: на гидратируемых страницах ожидание модуля
  маршрута **до** `hydrateRoot` — это и есть пауза; гидратировать сразу, как только модуль первого
  экрана готов, остальное — Suspense с уже отрендеренной разметкой (React 18 умеет гидратировать
  Suspense-границы по мере прихода чанков).

## 5. Пакет D — плавность после загрузки (60 к/с)

- [ ] D1. Профилирование главной на телефоне ×4: прокрутка через все секции, запись длинных задач и

- [ ] D2. `content-visibility: auto` + `contain-intrinsic-size` на секциях ниже первого экрана
  (Услуги, Кейсы, Отзывы, Блог, Форма, Подвал) — браузер не раскладывает невидимое. Не меняет вид.
- [ ] D3. Все `will-change` — только на время анимации; проверить слои композитора на главной и
  `/consult/` (DPR 3 → память видеокарты).
- [ ] D4. Анимации появления (`m.*` с `whileInView`): убедиться, что они на transform/opacity, без
  `layout`; на телефоне — проверить, что нет JS-петель (`repeat: Infinity`) ни на одной странице

- [ ] D5. Карусель статей на главной и список блога: `passive` слушатели, нет чтения геометрии в

- [ ] D6. Переходы между страницами: предзагрузка маршрута по наведению/касанию/появлению ссылки

- [ ] D7. Прокрутка «назад» без прыжка и без перерисовки (F-003/F-004/F-012 — высокие находки аудита).
