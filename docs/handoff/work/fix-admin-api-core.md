## Записи

- **F-075** — fixed — `scripts/import-articles.mjs` — перед отправкой один `GET /api/admin/articles?view=summary`; для статьи, которая уже есть в базе, статус берётся из базы (меняется только явным `--status`, для вышедшей статьи `--status draft` печатает «ВНИМАНИЕ»), дата выхода не отправляется (сервер хранит прежнюю через COALESCE), обложка/date/caseData/seoTitle/seoDescription/tags/keyTakeaways/faq берутся из базы, если их нет в JSON. Без списка статей импорт останавливается (код 2). Шапка скрипта переписана. `id` из файла больше не отправляется (см. F-019). Тест: спавн скрипта против локального http-сервера.
- **F-019** — fixed — `functions/api/admin/articles.ts`, `functions/_lib/d1.ts` — PATCH с `id > 0`, у которого в базе (D1 или JSONBin) этот id под другим слагом, отвечает 409 `SLUG_CHANGE_FORBIDDEN` с `currentSlug`; копия (id 0) и статья без id сохраняются как раньше. Клиентская часть (поле slug readOnly при id>0, подсказка в Admin.tsx) — группа admin-shell.
- **F-020** — fixed — `functions/_lib/jsonbin.ts` — введённые владельцем seoTitle (до 120), description (до 2000), seoDescription (до 220) не обрезаются; подстановки режутся по границе слова с «…» (`cutAtWord`: заголовок → seoTitle до 120, выжимка из текста → description до 160, description → seoDescription до 160, summary до 350). Данные в D1 (7 строк с 70-символьным seo_title) — владелец: `UPDATE articles SET seo_title = title WHERE length(seo_title) = 70 AND length(title) > 70 AND substr(title, 1, 70) = seo_title;`. `scripts/generate-pages.js:540` (`.slice(0, 160)`) — группа routing/build.
- **F-024** — fixed — `functions/_lib/jsonbin.ts`, `functions/_lib/d1.ts` — черновик без даты не получает publishedAt (в D1 пишется NULL); первое «опубликовать» без даты даёт текущее время; статья, которая выходила и была снята, дату сохраняет (previous.publishedAt главнее). Запасной `previous.updatedAt` остался только для ранее опубликованных без даты. Черновики, которым импорт уже проставил дату создания, данными не отличить — раскладывать «Расписанием» или править в редакторе. Подпись «оставьте пустой для немедленной» в Admin.tsx теперь правдива для новых черновиков.
- **F-129** — fixed — `functions/_lib/jsonbin.ts` — `notBeforePublication`: итоговый updatedAt не раньше publishedAt (сравнение через Date.parse) в обеих ветках applyFreshnessMetadata. Страховка на выходе (seo.ts, sitemap.xml.ts, generate-pages.js, BlogPage.tsx → max(updatedAt, publishedAt)) — чужие файлы, см. crossGroup.
- **F-080** — fixed — `functions/api/admin/page-locks.ts` — `unlock_all` обнуляет `locked_at`; upsert в `save` ставит новую дату, если прежний статус строки был «открыта» (чинит и строки, испорченные прошлыми «Открыть все»), правка текстов у закрытой страницы дату не сбрасывает. Разовый SQL не нужен.
- **F-081** — fixed — `functions/api/admin/page-locks.ts` — оба catch: `isMissingSchemaError` → MIGRATION_REQUIRED, иначе 503 `code: 'DB_ERROR'` с настоящим текстом ошибки и без поля `migration` (экран миграции в AdminPageLocks.tsx включается по `payload.migration`, так что ложный экран исчезает без правки клиента). Кнопка «Проверить снова» и условие `code === 'MIGRATION_REQUIRED'` в AdminPageLocks.tsx — группа admin-shell/ops.
- **F-091** — fixed — то же исправление, что F-081 (одна и та же пара catch).
- **F-082** — fixed — `functions/_lib/page-lock-preview.ts` — `sameSiteLocation(target)`: ведущие `/`/`\` склеиваются в один, `Location` всегда остаётся на своём домене (оба редиректа: `?ww_preview=off` и обмен ссылки на cookie).
- **F-083** — fixed — `functions/api/page-lock-notify.ts` — замок ищется по фактическому адресу (`findPageLock` с учётом `includeChildren`), человек возвращается на тот же адрес, если он под замком и проходит `^\/(?!\/)[A-Za-z0-9\-._~%/]+$` без сегментов `.`/`..`; в базу/Telegram/Meta по-прежнему уходит `lock.path`. Согласие, хеширование и event_id не тронуты.
- **F-084** — fixed — `functions/api/meta-test-event.ts` — третий допуск: действующая сессия админки (`hasValidAdminSession`); голый пароль принимается только при выключенной 2FA (`isAdmin2faEnabled`), как в `api/admin/_middleware.ts`. Текст 403 больше не отсылает к секрету. `npm run test:meta-capi` зелёный. CLAUDE.md/AGENTS.md строка «Допуск двойной» → тройной — не трогал (запрет), см. crossGroup.
- **F-094** — fixed — то же исправление, что F-084.
- **F-095** — fixed (серверная часть) — `functions/api/admin/_middleware.ts`, `scripts/admin-client.mjs` — 401 при включённой 2FA без сессии теперь `{ code: 'SESSION_EXPIRED', error: 'Сессия истекла — войдите в админку заново' }`; скрипт админки входит заново по этому коду (старые тексты тоже распознаёт). Срок сессии не продлевается намеренно (модель защиты). Клиентская часть (окно «войдите снова» поверх раздела без размонтирования, проверка сессии на focus/раз в 5 минут) — группа admin-shell.
- **F-092** — fixed — `functions/api/admin/upload.ts` — расширение берётся из исходного имени до очистки, основа транслитерируется той же таблицей, что в редакторе (`Договор.pdf` → `dogovor.pdf`), двойное расширение не пропускается; сверка MIME↔расширение и запрет SVG/HTML/JS не ослаблены; тексты ошибок валидации по-русски.
- **F-111** — fixed (серверная часть) — `functions/api/admin/media.ts`, `functions/api/admin/upload.ts` — `action: 'move'` принимает `keys[]` (до 50) и отвечает `{ moved, failed }`, одиночный `key` работает как раньше; оба роута используют профиль `admin_media`. Сам профиль в `functions/_lib/rate-limit.ts` (например `{ windowSeconds: 60, maxRequests: 240 }`) и клиент (AdminMedia: один запрос на пачку, ожидание Retry-After при 429, `load()` в finally) — чужие файлы, без профиля действует лимит по умолчанию 30/мин, но уже отдельным счётчиком.

- **F-111 (доработка по ревью)** — fixed — `functions/api/admin/media.ts`, `scripts/audit-admin-api-core.test.js` — пачечный `move` больше не вылетает голым 500: каждый `moveUpload` в try/catch, бросок хранилища (сеть, «Too many subrequests») записывается в `failed` как «Перенос прерван: …», пачка останавливается, остальные ключи возвращаются в `skipped`, ответ 200 `{ moved, failed, skipped, error }` с подсказкой «обновите список — файл мог остаться в обеих папках». Пачка режется заранее по бюджету подзапросов (`MOVE_BUDGET = 42`, `moveCost = 5 + 4 × копии`: картинка с четырьмя копиями ~21 вызов, документ 5), а не по числу ключей: 5 картинок с копиями стоили бы 100 обращений при 50 на запрос у бесплатного тарифа. Остаток клиент шлёт следующим запросом, пока `skipped` не пуст. Тесты: бросок на втором файле → moved=[первый], failed=[второй], третий не тронут и обращений после броска нет; три картинки по 2200 px → две за запрос (≤ 42 обращений R2), третья в `skipped` и переезжает вторым запросом.
