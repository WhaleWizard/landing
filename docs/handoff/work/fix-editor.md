id · статус · файлы · что сделано. Если сессия оборвалась — продолжать с первой находки, которой здесь нет.

Тест группы: `node --test scripts/audit-editor.test.js` (настоящие `ArticleEditor` и `CaseFieldsEditor`, собранные esbuild в памяти и смонтированные в jsdom; разбор и сборка HTML — через экспортированные помощники редактора).

Порядок: F-006, F-008, F-022, F-023, F-059, F-064.

## Журнал (02.10.2026)

- F-006 · fixed · ArticleEditor.tsx · (1) `parseNodeToBlock`: p/blockquote с разметкой кроме `<br>`, h2/h3 с любым тегом, акцент/карточка не из «чистого текста или одного <p>», список с тегом внутри `li` — возвращаются `{ type: 'rawHtml', html: outerHTML }` без потерь (помощники `hasInlineMarkup`, `isPlainTextContainer`); текстовые блоки по-прежнему текстом. (2) `blocksTouchedRef`: onChange уходит только после настоящей правки (setBlocksWithHistory с новым массивом, undo/redo); внешняя смена `content` сбрасывает флаг — монтирование и перерисовка родителя статью больше не переписывают. Экспортированы `parseHtmlToBlocks`/`serializeBlocks`/`markdownToBlocks`/`blockToMarkdown` для теста. Проверено на всех 13 статьях `data/articles.build.json`: число `<a>`/`<strong>`/`<em>` до и после совпадает. Стык (необязательный): `handleContentChange` в Admin.tsx обернуть в `useCallback` — с флагом уже не требуется для корректности.
- F-008 · fixed · ArticleEditor.tsx · Markdown — источник правды, пока режим открыт: `mdBaselineRef`/`mdAppliedRef`/`mdEntryBlocksRef` ставятся при входе; эффект на `[markdownMode, mdText]` через 220 мс вызывает `applyMarkdown` → `setBlocksWithHistory(markdownToBlocks(md))` + `setHtmlOutput` сразу → обычная цепочка onChange (метка «есть изменения», резервная копия, подтверждение при «Отмене», сохранение). Текст без правок (равен baseline) не применяется — переключение туда-обратно не переписывает статью и не снимает акцент; возврат текста к исходному возвращает исходные блоки. `onBlur` поля Markdown применяет текст синхронно (клик по «Сохранить» сначала снимает фокус). «Применить разметку»/«Визуальный» — тот же `applyMarkdown`. В режиме Markdown палитра «Добавить блок», Undo/Redo и Ctrl+Enter выключены (addBlock менял бы блоки в обход текста). Стык (необязательный): `flush()` через ref для `handleSave` в Admin.tsx — blur уже закрывает гонку.
- F-022 · fixed · ArticleEditor.tsx · `handlePaste` больше не перехватывает обычную вставку: без `text/html` или с текстом в буфере обработчик выходит, и браузер сам вставляет по курсору с заменой выделения и Ctrl+Z. `preventDefault` только когда в HTML буфера ровно один `<img>` и нет текста — тогда `onUpdate(block.id, { type: 'image', imageUrl, imageAlt })` (раньше менялся один imageUrl у абзаца, и картинка не появлялась). HTML буфера разбирается через `DOMParser` (неактивный документ, `<img>` не грузится).
- F-023 · fixed · ArticleEditor.tsx · в ветке внешней синхронизации эффекта `[content]` — `setMarkdownMode(false); setMdText('')`: другая статья или восстановленная версия закрывает Markdown вместе с чужим текстом; своя правка (isLocalSyncRef) режим не трогает. Вариант с `key` по слагу не брался — слаг меняется на каждой букве заголовка.
- F-059 · fixed · CaseFieldsEditor.tsx · `setMetric` хранит все три слота как есть (пустые тоже), совсем пустой набор → `metrics: undefined`. Пустые и неполные метрики отбрасывает сервер при чтении (`normalizeCaseData` в `_lib/jsonbin.ts`, D1-путь `_lib/d1.ts:80`). Стык (необязательный, аккуратнее для D1): в `handleSave` Admin.tsx пропустить `caseData.metrics` через `.filter((m) => m.value.trim() && m.label.trim())`, пустой массив → undefined.
- F-064 · fixed · ArticleEditor.tsx · в существующий keydown-эффект добавлены сочетания по `event.code`: Alt+Shift+ArrowUp/Down → `moveBlockByArrow` для выбранного блока; Ctrl/Cmd+Z → undo, Ctrl/Cmd+Y и Ctrl/Cmd+Shift+Z → redo — только когда курсор не в input/textarea/select/contenteditable (цель внутри `.admin-article-editor` или body — после удаления блока фокус уходит на body); в режиме Markdown всё молчит. Эффект перенесён ниже `undo`/`redo` (иначе TDZ в массиве зависимостей). Подсказка под палитрой уточнена: когда работает отмена.

## Доработка по ревью (02.10.2026)

- F-008 · fixed (доработано) · ArticleEditor.tsx, scripts/audit-editor.test.js · Ревьюер воспроизвёл гонку на настоящем родителе: onChange уходил из пассивного эффекта `[htmlOutput, content, onChange]`, а setState из пассивного эффекта React понижает до Default-приоритета и выполняет задачей планировщика (макрозадача). Тап на телефоне отдаёт blur, mouseup и click в одной задаче — между слушателями только микрозадачи, и «Сохранить» читал старый `content`, а «Отмена» видела hasUnsaved=false; onBlur это не закрывал. Теперь `applyMarkdown` (blur, «Визуальный»/«Применить разметку», отложенная синхронизация) отдаёт HTML родителю синхронно внутри события: `if (html !== content) { mdHandedHtmlRef = html; isLocalSyncRef = true; onChange(html) }`, зависимости `[content, onChange, setBlocksWithHistory]` — обновление родителя идёт с приоритетом события и сбрасывается на микрозадаче до click. `mdHandedHtmlRef` не даёт эффекту повторить тот же HTML (одна правка — один onChange), сбрасывается при внешней смене `content`. Тест: родитель с `content` в useState и кнопками, читающими его из замыкания; без act(): blur → только микрозадачи → click «Сохранить»/«Отмена» — видят новый текст и hasUnsaved=true (на старом коде падал: «Сохранить» получал старый content); та же проверка для выхода кнопкой «Визуальный» без blur; плюс проверка «один onChange». Стык flush() через ref в Admin.tsx теперь не нужен.

Итого: 6/6 исправлено. Тест `scripts/audit-editor.test.js` (15 проверок) — добавить в package.json как `test:audit-editor` и в цепочку `check` (чужой файл).
