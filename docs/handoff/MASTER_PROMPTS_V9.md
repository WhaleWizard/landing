## Почему понадобилась v9

Что показал прогон Codex (14–22.11) и мой (25.11) по старым промптам:

| Проблема старых промптов | Что из-за неё случилось | Что в v9 |
| --- | --- | --- |
| Восемь промптов пересекаются (v1, v3, v4, v6, v7, v8 повторяют друг друга), v1–v2 — пересказ, а не оригинал | Агент тратит время на сверку промптов между собой, а не на сайт | Шесть промптов без пересечений, у каждого своя зона |
| Список разделов админки дан словами («пройди Сегодня, планер…»), без обязательной таблицы покрытия | Codex пропустил 5 разделов, которые были прямо названы | Жёсткий шлюз: таблица всех разделов из `Admin.tsx`, ни одной строки «не начато» к финалу |
| Нет правила калибровки серьёзности для админки одного человека | Треть P1 — «две вкладки одновременно», реальные риски тонут | Шкала с примерами; сценарий «две вкладки» — P2, если нет потери данных в обычной работе |
| Безопасность — одна строка («XSS, CSRF, secrets») | Пропущен подбор пароля через `/api/articles` (CL-16) и XSS в редакторе (CL-18) | Отдельный список проверок: оракулы пароля, все точки вне middleware, все «синки» HTML, открытые редиректы, SSRF, CSV-формулы |
| Нет проверки знаний предметной области | Чек-лист советует «5 × CPL», что противоречит «50 конверсий в неделю»; LCP перепутан с FCP | Промпт E: факты о Meta/Google, формулы, подсказки сверяются с первоисточником |
| Нет рецептов статического поиска | Классы ошибок (`\b` с кириллицей, `toISOString().slice(0,10)` для «сегодня» в Ташкенте, `Number(x) \|\| 0`) находятся по одной | Приложение A: обязательные поиски по шаблонам, каждый результат — разобран |
| Визуал админки предлагается «в браузере», а локально разделы без базы показывают заглушку | Визуальный аудит админки делался на пустых экранах или вообще не делался | Обязательный стенд с SQLite, миграциями и наполнением (Приложение B) |
| Замеры скорости без ограничения по времени | Дни на 50 прогонов Lighthouse и поиск одного предупреждения React | Лимит времени и правило остановки для каждого эксперимента |
| Отчёт — сплошной текст | Владельцу не прочитать 266 КБ прозы | Формат: короткая сводка → таблица → подробности (Приложение C) |
| Доказательства в `output/` вне git | На другом ПК реестр теряет смысл | Короткая выжимка каждого доказательства — в самом реестре |

## Приложение D. Сканер вёрстки (минимум)

На каждом экране после загрузки шрифтов и окончания анимаций: `document.documentElement.scrollWidth > clientWidth`;
для каждого видимого элемента с текстом — `getBoundingClientRect` за пределами окна, `scrollWidth > clientWidth`
при `overflow: hidden`; пересечение прямоугольников соседних кнопок/ссылок; размер целей касания; вычисленный
`font-size`; для заголовков — `Range.getClientRects()` по словам: одно слово на последней строке, разрыв между
«Meta» и «Ads», между числом и единицей; `img` без `width/height`; поля без доступного имени.
